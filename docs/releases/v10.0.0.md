# Socket v10.0.0

Socket 10 establishes one permanent Swift product workspace and one protected-main
Socket release lifecycle.

## What changed

- `bootstrap-xcode-workspace` is now the only Swift repository create, adopt,
  add-component, and align entrypoint.
- Existing hand-managed Xcode, XcodeGen, package-only, service-only, and mixed
  repositories can be adopted through a reviewed component map.
- Applications, app extensions, and Xcode test targets are peers under `Apps/`;
  extension host embedding is explicit.
- Reusable packages live under `Packages/` and deployable Swift services under
  `Services/` without repository-shape classification.
- Soto is the default Swift AWS SDK. Deviations require a recorded exception.
- Native macOS Swift execution with Homebrew services is the sole standard local
  server-development path.
- GitHub Actions exclusively builds Linux images and owns test and production
  cloud deployments from immutable artifacts.
- Socket releases now use one branch-backed `prepare` → `inspect` → `advance`
  workflow with full local and GitHub validation, reviewed-main evidence,
  annotated tags, structured branch accounting, and marketplace refresh last.

## Breaking changes

- Removed the standalone Swift package bootstrap, old XcodeGen migrator, broad
  SwiftPM/Xcode compatibility routers, and `swift-package`/`xcode-app`
  repository-maintenance profiles.
- Removed the Server-Side Swift Apple-container workflow, duplicate local
  environment templates, local Compose/image/VM development paths, and direct
  developer Fly deployment path.
- Removed Socket's direct-main `patch-refresh`, version-only mutation commands,
  separate release modes, and blanket unmerged-branch override.

## Migration

- Run `bootstrap-xcode-workspace --operation adopt` once for an existing Swift
  repository, review the emitted component map, then apply that exact map.
- Move app extensions to peer targets under `Apps/` and record their host target
  explicitly.
- Use native Homebrew services for local server dependencies and move all Linux
  artifact/deployment work into GitHub Actions.
- For future Socket releases, author `docs/releases/vX.Y.Z.md`, then use
  `scripts/release.sh prepare`, `inspect`, and `advance`.

## Verification gates

- Full Socket validation on the release branch and reviewed `main`.
- Required GitHub `validate` check using the full validation profile.
- Hermes and Claude Code/Cowork compatibility validation.
- Apple Dev Skills documentation and behavioral suites.
- Temporary isolated Socket marketplace add/remove smoke test.
- Current Dependabot alert query.
